4. Escalations discovered by this audit (needs user sign-off before Phase 3)
================================================================================

ESC-1  api/jobs.py:73-137 uses allowed_device_names_for + ensure_device_allowed
       for list/retry/cancel. Plan §20.2 does not enumerate jobs.py explicitly.
       Recommendation: convert to require_scope with the device's group scope in
       Phase 3 T3.4b. No new endpoints needed.

ESC-2  api/ports.py has 8 write endpoints + 1 read endpoint using ensure_device_
       allowed. Convert to require_scope('write_device_config' / 'read_device')
       in Phase 3 T3.4b. Mechanical change; ~9 line edits.

ESC-3  api/vlans.py has 5 endpoints using ensure_device[s]_allowed. Same
       mechanical conversion in Phase 3 T3.4b.

ESC-4  api/auth.py:156 unlock_account uses require_role("admin"). Not in plan
       §12.3. Recommendation: promote to require_system_admin. Reason: unlock is
       a security-sensitive op tied to a single user record with no site scope.

ESC-5  R7 (multi-group device audit — T0.6) must run against production data
       before Phase 4. If any device is in >1 group in the same site, the
       ambiguous-assignment audit-log side effect (M2 Step 4) preserves the
       history but the operator must be aware.

ESC-6  R4 (Base-Infrastructure name collision — T0.7) must run against
       production data before Phase 1 deploys, because
       ensure_base_infrastructure() will attempt to INSERT a site named
       "Base Infrastructure" on first boot.
